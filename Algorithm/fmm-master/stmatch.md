# STMATCH 算法原理详解 - 通俗版

## 一、算法是什么？解决什么问题？

### 问题场景
想象一下，你有一辆车的GPS轨迹数据（一串经纬度点），但是GPS有误差，这些点可能偏离了实际行驶的道路。你需要把这些GPS点"贴"到正确的道路上，这个过程就叫"地图匹配"。

### STMATCH 的核心思想
STMATCH（Hidden Markov Model based Map Matching）是一种基于隐马尔可夫模型的地图匹配算法，它的核心特点是：
- **实时计算最短路径**：使用Dijkstra算法动态计算候选点之间的路径
- **考虑时空约束**：通过速度限制来约束搜索范围，提高效率
- **无需预处理**：不需要提前计算UBODT表，适合实时匹配场景

## 二、算法完整流程（6个步骤）

---

### 步骤1：候选点搜索 - 找GPS点可能在哪些路上

#### 1.1 为什么要找候选点？
一个GPS点可能对应多条道路（比如在路口附近），所以需要找到所有可能的道路段，然后从中选出最合适的。

#### 1.2 具体怎么找？（详细步骤）

**输入**：一个GPS点（坐标：px, py）、参数k=8、radius=300米

**第一步：画个圈**
- 以GPS点为中心，画一个边长为2*radius的正方形（300米半径，就是600米边长的正方形）
- 这个正方形就是"搜索范围"

**第二步：快速找出圈内的道路**
- 使用R-tree（一种空间索引结构，像地图的目录）快速查找
- 找到所有与这个正方形相交的道路边

**第三步：计算每条道路的最近点**
对找到的道路边，每条都要做这些事：
- 找到这条道路上距离GPS点最近的点（投影点）
- 计算两个距离：
  - `dist`：GPS点到投影点的直线距离
  - `offset`：投影点在道路上的位置（从道路起点算起多少米）

**第四步：筛选**
- 如果 `dist <= radius`（300米），就保留这个候选点
- 否则，这条道路太远了，不要

**第五步：选最好的k个**
- 按距离从小到大排序
- 只保留最近的k个（比如8个）

**输出**：这个GPS点对应的k个候选点

每个候选点包含的信息：
- `edge_id`：在哪条道路上
- `point`：投影点坐标
- `offset`：在道路上的位置（米）
- `dist`：到原始GPS点的距离（米）

**代码位置**：`network.cpp:240-294`（通过`search_tr_cs_knn`函数调用）

---

### 步骤2：构建转移图 - 把候选点连起来

#### 2.1 什么是转移图？
把轨迹上每个GPS点的候选点都画出来，然后按时间顺序排列，形成一个"图"。

```
时间点1的候选点：   [候选1-1]  [候选1-2]  [候选1-3]
时间点2的候选点：   [候选2-1]  [候选2-2]  [候选2-3]
时间点3的候选点：   [候选3-1]  [候选3-2]  [候选3-3]
```

每一行叫一个"层"（Layer），每个候选点叫一个"节点"（Node）。

#### 2.2 计算发射概率（Emission Probability）

发射概率 = 这个候选点真的是GPS点的可能性有多大？

计算公式（高斯分布）：
```
发射概率 = exp(-0.5 × (距离 / GPS误差)²)
```

**例子**：
- 候选点A：距离GPS点10米，GPS误差50米
  - 发射概率 = exp(-0.5 × (10/50)²) = exp(-0.02) = 0.98
- 候选点B：距离GPS点100米，GPS误差50米
  - 发射概率 = exp(-0.5 × (100/50)²) = exp(-2) = 0.135

**结论**：距离越近，发射概率越高（越可能是正确的）

**代码位置**：`transition_graph.cpp:27-29`

#### 2.3 初始化转移图
- 对每个候选点，计算发射概率
- 第一层的候选点：累积概率 = 发射概率（因为它是起点）
- 其他层的候选点：累积概率 = -∞（还没计算）

**代码位置**：`transition_graph.cpp:14-28`

---

### 步骤3：构建组合图（Composite Graph）

#### 3.1 什么是组合图？
组合图 = 路网图 + Dummy图

**Dummy图**：把每个候选点当作虚拟节点，连接到其所在道路的起点和终点

**组合图的作用**：让候选点可以通过路网图连接起来，方便后续的最短路径计算

**代码位置**：`stmatch_algorithm.cpp:137`（`CompositeGraph cg(graph_, dg)`）

---

### 步骤4：更新转移概率 - 计算从A到B的可能性

这是算法的核心步骤！

#### 4.1 为什么要算转移概率？
不仅要看单个候选点是否合理，还要看"从上一个候选点到这个候选点"是否合理。

#### 4.2 计算搜索上限 delta

**关键优化**：根据时间约束限制搜索范围

情况1：有时间戳数据
```
delta = factor × vmax × duration
其中：
- duration = 两个GPS点之间的时间差
- vmax = 最大车速（如30米/秒）
- factor = 安全系数（如1.5）
```

情况2：无时间戳数据
```
delta = 欧氏距离 × factor × 4
```

**代码位置**：`stmatch_algorithm.cpp:267-273`

#### 4.3 逐层计算（动态规划）

对每一对相邻的层（时间点i和时间点i+1）：

**第一步：计算GPS点之间的欧氏距离**
```
欧氏距离 = 两点之间的直线距离
```

**第二步：遍历所有候选点组合**
- 对层i的每个候选点ca
- 对层i+1的每个候选点cb
- 使用带上限的Dijkstra算法计算ca到cb的最短路径距离

**第三步：带上限的最短路径搜索（关键优化！）**

使用Dijkstra算法，但有一个重要的停止条件：
```
如果当前搜索的距离 > delta，则停止搜索
```

这样可以大大减少搜索范围，提高效率。

**代码位置**：`stmatch_algorithm.cpp:316-386`（`shortest_path_upperbound`函数）

**第四步：计算转移概率**

公式：
```
转移概率 = min(欧氏距离 / 最短路径距离, 1.0)
```

**例子**：
```
欧氏距离 = 200米
最短路径距离 = 230米

转移概率 = 200 / 230 = 0.87
```

**代码位置**：`transition_graph.cpp:24-26`

**第五步：更新累积概率（动态规划核心）**

```
新累积概率 = 上一个候选点的累积概率 + log(转移概率) + log(发射概率)

如果 新累积概率 >= 当前候选点的累积概率：
    更新累积概率
    记录上一个候选点为前驱
```

**代码位置**：`stmatch_algorithm.cpp:298-311`

---

### 步骤5：最优路径推断 - 回溯找到最佳路径

#### 5.1 回溯过程（Viterbi算法）

**第一步：找最后一层的最优节点**
```
在最后一层，找到累积概率最大的候选点
```

**第二步：往前回溯**
```
通过prev指针，一步步往前找：
  最优候选点N → 最优候选点N-1 → ... → 最优候选点1
```

**第三步：反转顺序**
```
回溯得到的是倒序的，需要反转回来
```

**代码位置**：`transition_graph.cpp:56-88`（`backtrack`函数）

---

### 步骤6：路径重构 - 把候选点连成完整道路

#### 6.1 构建完整路径（Complete Path）

**问题**：候选点之间可能隔着很多条路，需要把中间的路都补上。

**方法**：使用Dijkstra算法补全路径
- 查询候选i所在路的终点到候选i+1所在路起点的路径
- 把中间的路都加进来

**代码位置**：`stmatch_algorithm.cpp:388-428`（`build_cpath`函数）

#### 6.2 生成几何轨迹

根据边ID序列，从路网中提取几何信息，生成一条线串。

**代码位置**：`stmatch_algorithm.cpp:165-166`

## 三、算法参数怎么调？

| 参数 | 默认值 | 含义 | 调整建议 |
|-----|-------|-----|---------|
| k | 8 | 每个GPS点选几个候选点 | 道路密集的地方可以加大到12-16 |
| radius | 300 | 搜索半径（米） | GPS误差大时可以加大到500 |
| gps_error | 50 | GPS误差标准差（米） | 根据GPS设备精度调整 |
| vmax | 30 | 最大车速（米/秒） | 根据实际交通状况调整 |
| factor | 1.5 | 安全系数 | 车流稀疏时可增大到2.0 |
| reverse_tolerance | 0 | 允许反向行驶的比例 | 0.1表示允许10%的反向 |

## 五、关键公式（用文字描述）

### 5.1 发射概率
```
发射概率 = e的(-0.5 × (距离/GPS误差)²) 次方

含义：GPS点到候选点的距离越近，这个候选点越可能是正确的
```

### 5.2 转移概率
```
转移概率 = min(欧氏距离 / 最短路径距离, 1.0)

含义：如果GPS点间直线距离和道路距离差不多，说明这条路很合理
```

### 5.3 累积概率
```
累积概率 = 上一候选点的累积概率 + log(转移概率) + log(发射概率)

含义：从起点到这个候选点的总概率（用对数避免数值太小）
```

### 5.4 搜索上限 delta
```
有时间戳：delta = factor × vmax × duration
无时间戳：delta = 欧氏距离 × factor × 4

含义：限制最短路径搜索的范围，提高效率
```

## 七、FMM vs STMATCH 对比

| 特性 | FMM | STMATCH |
|-----|------|---------|
| **最短路径计算** | 预计算UBODT表 | 实时Dijkstra |
| **预处理** | 需要（构建UBODT） | 不需要 |
| **查询速度** | 极快（O(1)查表） | 较慢（每次计算） |
| **内存占用** | 较大（存储UBODT） | 较小 |
| **适用场景** | 批量处理大量轨迹 | 实时匹配、内存受限 |
| **搜索范围控制** | 使用UBODT的delta参数 | 使用速度×时间约束 |
| **时间戳利用** | 不直接使用 | 用于计算delta上限 |

## 八、总结

### STMATCH的核心特点

1. **实时计算**
   - 不需要预计算UBODT表
   - 适合实时匹配场景
   - 路网变化时无需重新预处理

2. **时空约束**
   - 通过速度和时间计算搜索上限delta
   - 减少不必要的路径搜索
   - 提高算法效率

3. **HMM概率模型**
   - 发射概率：考虑GPS误差
   - 转移概率：考虑道路连通性
   - 动态规划找最优路径

### 适用场景

✅ 适合：
- 实时地图匹配
- 内存受限的环境
- 路网频繁变化的场景
- 小规模轨迹数据处理

❌ 不适合：
- 大规模批量轨迹处理（速度慢）
- 需要极致性能的场景
