# FMM (Fast Map Matching) 算法原理详解 - 通俗版

## 一、算法是什么？解决什么问题？

### 问题场景
想象一下，你有一辆车的GPS轨迹数据（一串经纬度点），但是GPS有误差，这些点可能偏离了实际行驶的道路。你需要把这些GPS点"贴"到正确的道路上，这个过程就叫"地图匹配"。

### FMM 的核心思想
FMM（Fast Map Matching）是一种快速地图匹配算法，它的核心创新是：
- **提前算好所有道路之间的最短路径**，存到一个表里（叫UBODT）
- 匹配时直接查表，不用每次都算最短路径
- 这样速度非常快，适合处理大量轨迹数据

## 二、算法完整流程（6个步骤）

---

### 步骤1：候选点搜索 - 找GPS点可能在哪些路上

#### 1.1 为什么要找候选点？
一个GPS点可能对应多条道路（比如在路口附近），所以需要找到所有可能的道路段，然后从中选出最合适的。

#### 1.2 具体怎么找？（详细步骤）

**输入**：一个GPS点（坐标：px, py）、参数k=8、radius=300米

**第一步：画个圈**
- 以GPS点为中心，画一个边长为2*radius的正方形（300米半径，就是600米边长的正方形）
- 这个正方形就是"搜索范围"

**第二步：快速找出圈内的道路**
- 使用R-tree（一种空间索引结构，像地图的目录）快速查找
- 找到所有与这个正方形相交的道路边
- 比如：找到了15条道路边

**第三步：计算每条道路的最近点**
对这15条道路边，每条都要做这些事：
- 找到这条道路上距离GPS点最近的点（投影点）
- 计算两个距离：
  - `dist`：GPS点到投影点的直线距离
  - `offset`：投影点在道路上的位置（从道路起点算起多少米）

**第四步：筛选**
- 如果 `dist <= radius`（300米），就保留这个候选点
- 否则，这条道路太远了，不要

**第五步：选最好的k个**
- 假设筛选后还有12个候选点
- 按距离从小到大排序
- 只保留最近的k个（比如8个）

**输出**：这个GPS点对应的8个候选点

每个候选点包含的信息：
- `edge_id`：在哪条道路上
- `point`：投影点坐标
- `offset`：在道路上的位置（米）
- `dist`：到原始GPS点的距离（米）

#### 1.3 举个具体例子

```
GPS点：(116.397, 39.908)

搜索半径：300米

找到的道路：
1. 道路A，距离10米，offset 50米
2. 道路B，距离20米，offset 120米
3. 道路C，距离15米，offset 80米
4. 道路D，距离280米，offset 200米
5. 道路E，距离350米，offset 300米  ← 超过300米，不要
...

按距离排序后取前8个：
候选点1：道路A，距离10米
候选点2：道路C，距离15米
候选点3：道路B，距离20米
候选点4：道路D，距离280米
...
```

**代码位置**：`network.cpp:240-294`

### 步骤2：构建转移图 - 把候选点连起来

#### 2.1 什么是转移图？
把轨迹上每个GPS点的候选点都画出来，然后按时间顺序排列，形成一个"图"。

```
时间点1的候选点：   [候选1-1]  [候选1-2]  [候选1-3]
时间点2的候选点：   [候选2-1]  [候选2-2]  [候选2-3]
时间点3的候选点：   [候选3-1]  [候选3-2]  [候选3-3]
```

每一行叫一个"层"（Layer），每个候选点叫一个"节点"（Node）。

#### 2.2 计算发射概率（Emission Probability）

发射概率 = 这个候选点真的是GPS点的可能性有多大？

计算公式（高斯分布）：
```
发射概率 = exp(-0.5 × (距离 / GPS误差)²)
```

**例子**：
- 候选点A：距离GPS点10米，GPS误差50米
  - 发射概率 = exp(-0.5 × (10/50)²) = exp(-0.02) = 0.98
- 候选点B：距离GPS点100米，GPS误差50米
  - 发射概率 = exp(-0.5 × (100/50)²) = exp(-2) = 0.135

**结论**：距离越近，发射概率越高（越可能是正确的）

**代码位置**：`transition_graph.cpp:27-29`

#### 2.3 初始化转移图
- 对每个候选点，计算发射概率
- 第一层的候选点：累积概率 = 发射概率（因为它是起点）
- 其他层的候选点：累积概率 = -∞（还没计算）

**代码位置**：`transition_graph.cpp:14-28`

---

### 步骤3：更新转移概率 - 计算从A到B的可能性

这是算法的核心步骤！

#### 3.1 为什么要算转移概率？
不仅要看单个候选点是否合理，还要看"从上一个候选点到这个候选点"是否合理。

比如：
- 上一个候选点在"长安街"
- 这个候选点在"二环路"
- 从长安街到二环路，需要走多远？是不是合理？

#### 3.2 逐层计算（动态规划）

对每一对相邻的层（时间点i和时间点i+1）：

**第一步：计算GPS点之间的欧氏距离**
```
欧氏距离 = 两点之间的直线距离
```

例子：GPS点1到GPS点2的直线距离 = 200米

**第二步：遍历所有候选点组合**
- 对层i的每个候选点ca
- 对层i+1的每个候选点cb
- 计算从ca到cb的转移概率

**第三步：计算最短路径距离（关键优化！）**

使用UBODT表快速查找，不用实时计算Dijkstra：

情况1：同一条路上
```
如果ca和cb在同一条路上，且ca在cb前面：
最短路径距离 = cb的offset - ca的offset
```

情况2：允许反向行驶（比如掉头）
```
如果ca和cb在同一条路上，但ca在cb后面，且反向距离很小：
最短路径距离 = 0（允许掉头）
```

情况3：相邻路直接连着
```
如果ca所在路的终点 = cb所在路的起点：
最短路径距离 = ca所在路剩余长度 + cb的offset
```

情况4：需要查UBODT表（最常见）
```
最短路径距离 = UBODT查询结果 + ca到路终点的距离 + cb到路起点的距离
```

**例子**：
```
ca：道路A，offset 50米，道路A长度100米
cb：道路B，offset 30米

UBODT查询：道路A终点到道路B起点 = 150米

最短路径距离 = 150 + (100-50) + 30 = 230米
```

**代码位置**：`fmm_algorithm.cpp:254-274`

**第四步：计算转移概率**

公式：
```
如果 欧氏距离 >= 最短路径距离：
    转移概率 = 1.0
否则：
    转移概率 = 欧氏距离 / 最短路径距离
```

**例子1**：
```
欧氏距离 = 200米
最短路径距离 = 230米

转移概率 = 200 / 230 = 0.87
```

**例子2**：
```
欧氏距离 = 200米
最短路径距离 = 180米

转移概率 = 1.0（因为GPS误差可能导致直线距离小于实际路径）
```

**代码位置**：`transition_graph.cpp:24-26`

**第五步：更新累积概率（动态规划核心）**

```
新累积概率 = 上一个候选点的累积概率 + log(转移概率) + log(发射概率)

如果 新累积概率 >= 当前候选点的累积概率：
    更新累积概率
    记录上一个候选点为前驱
```

**为什么要用对数？**
- 避免很多小数相乘导致数值太小
- 对数域的加法 = 原始域的乘法

**例子**：
```
候选点2-1：
  从候选1-1来：累积概率 = -0.5 + log(0.87) + log(0.98) = -0.66
  从候选1-2来：累积概率 = -0.3 + log(0.5) + log(0.98) = -0.99

选择：从候选1-1来更好，累积概率 = -0.66
```

**代码位置**：`fmm_algorithm.cpp:298-332`

#### 3.3 完整例子

```
时间点1：GPS点(116.397, 39.908)
  候选1-1：道路A，距离10米，发射概率0.98
  候选1-2：道路B，距离20米，发射概率0.92
  候选1-3：道路C，距离30米，发射概率0.82

时间点2：GPS点(116.398, 39.909)，欧氏距离200米
  候选2-1：道路D，距离15米，发射概率0.96
  候选2-2：道路E，距离25米，发射概率0.88

计算候选2-1的累积概率：
  从1-1来：-0.02 + log(0.9) + log(0.96) = -0.16
  从1-2来：-0.08 + log(0.7) + log(0.96) = -0.45
  从1-3来：-0.20 + log(0.5) + log(0.96) = -0.70

  最优：从1-1来，累积概率-0.16

计算候选2-2的累积概率：
  从1-1来：-0.02 + log(0.6) + log(0.88) = -0.40
  从1-2来：-0.08 + log(0.95) + log(0.88) = -0.18

  最优：从1-2来，累积概率-0.18

时间点3：GPS点(116.399, 39.910)，欧氏距离180米
  ...（继续计算）
```

### 步骤4：最优路径推断 - 回溯找到最佳路径

#### 4.1 为什么要回溯？
步骤3计算了所有候选点的累积概率，现在要从最后一层开始，找到概率最大的路径。

#### 4.2 回溯过程（Viterbi算法）

**第一步：找最后一层的最优节点**
```
在最后一层，找到累积概率最大的候选点
```

**第二步：往前回溯**
```
通过prev指针，一步步往前找：
  最优候选点N → 最优候选点N-1 → ... → 最优候选点1
```

**第三步：反转顺序**
```
回溯得到的是倒序的，需要反转回来
```

**例子**：
```
最后一层（时间点3）：
  候选3-1：累积概率 -0.25
  候选3-2：累积概率 -0.15 ← 最优
  候选3-3：累积概率 -0.35

从候选3-2往前回溯：
  候选3-2.prev = 候选2-2
  候选2-2.prev = 候选1-1
  候选1-1.prev = null（起点）

最优路径：候选1-1 → 候选2-2 → 候选3-2
```

**代码位置**：`transition_graph.cpp:56-88`

### 步骤5：路径重构 - 把候选点连成完整道路

#### 5.1 提取匹配信息

从最优路径中提取每个候选点的详细信息：
- 边ID
- 投影点坐标
- 偏移量
- 发射概率
- 转移概率
- 最短路径距离

#### 5.2 构建完整路径（Complete Path）

**问题**：候选点之间可能隔着很多条路，需要把中间的路都补上。

**例子**：
```
候选1：道路A
候选2：道路C

中间缺了：道路B

完整路径：道路A → 道路B → 道路C
```

**方法**：使用UBODT表
- 查询候选1所在路的终点到候选2所在路起点的路径
- 把中间的路都加进来

**代码位置**：`fmm_algorithm.cpp:116-117`

#### 5.3 生成几何轨迹

根据边ID序列，从路网中提取几何信息，生成一条线串。

**代码位置**：`fmm_algorithm.cpp:122-123`

## 三、UBODT是什么？为什么这么快？

### 3.1 UBODT = Upperbounded Origin Destination Table

就是一个"最短路径查询表"，提前算好所有节点对之间的最短路径。

**存储内容**：
```
起点节点 | 终点节点 | 最短路径距离 | 下一跳节点
   1     |    2      |     150米    |    3
   1     |    3      |     100米    |    3
   2     |    3      |      50米    |    3
   ...
```

### 3.2 怎么构建？

使用Dijkstra算法，从每个节点出发搜索：
- 只搜索距离不超过delta的路径（比如5000米）
- 记录所有可达的节点和最短路径

### 3.3 为什么快？

| 方法 | 查询速度 | 预处理 | 内存 |
|-----|---------|--------|------|
| FMM (UBODT) | O(1) 直接查表 | 需要预计算 | 较大 |
| STMATCH (实时Dijkstra) | O(M + N log N) | 不需要 | 较小 |

**例子**：
```
实时Dijkstra：每次查询需要遍历很多节点，耗时几毫秒到几十毫秒
UBODT查表：直接哈希查找，耗时几微秒

速度提升：1000倍以上！
```

## 四、算法参数怎么调？

| 参数 | 默认值 | 含义 | 调整建议 |
|-----|-------|-----|---------|
| k | 8 | 每个GPS点选几个候选点 | 道路密集的地方可以加大到12-16 |
| radius | 300 | 搜索半径（米） | GPS误差大时可以加大到500 |
| gps_error | 50 | GPS误差标准差（米） | 根据GPS设备精度调整 |
| reverse_tolerance | 0 | 允许反向行驶的比例 | 0.1表示允许10%的反向 |

## 六、关键公式（用文字描述）

### 6.1 发射概率
```
发射概率 = e的(-0.5 × (距离/GPS误差)²) 次方

含义：GPS点到候选点的距离越近，这个候选点越可能是正确的
```

### 6.2 转移概率
```
如果 欧氏距离 >= 最短路径距离：
    转移概率 = 1.0
否则：
    转移概率 = 欧氏距离 / 最短路径距离

含义：如果GPS点间直线距离和道路距离差不多，说明这条路很合理
```

### 6.3 累积概率
```
累积概率 = 上一候选点的累积概率 + log(转移概率) + log(发射概率)

含义：从起点到这个候选点的总概率（用对数避免数值太小）
```

## 八、总结

### FMM的三个核心创新

1. **UBODT预计算**
   - 提前算好所有最短路径
   - 查询速度从毫秒级降到微秒级
   - 适合大规模批量处理

2. **HMM概率模型**
   - 发射概率：考虑GPS误差
   - 转移概率：考虑道路连通性
   - 综合判断，提高准确性

3. **动态规划优化**
   - 逐层计算累积概率
   - 避免指数级搜索
   - Viterbi回溯找最优路径

### 适用场景

✅ 适合：
- 大规模轨迹数据批量处理
- 路网相对稳定
- 需要高效率的场景

❌ 不适合：
- 实时匹配（需要预处理）
- 路网频繁变化
- 内存受限的环境

### 性能对比

| 指标 | FMM | STMATCH | 传统方法 |
|-----|------|---------|---------|
| 单条轨迹匹配时间 | <1ms | 10-100ms | 100-1000ms |
| 预处理时间 | 几小时 | 无 | 无 |
| 内存占用 | 几GB | 几百MB | 几十MB |
| 匹配精度 | 高 | 高 | 中 |

## 九、常见问题

### Q1：候选点k选多少合适？
A：一般8-12个。道路密集的地方可以加大，但会增加计算量。

### Q2：radius怎么设置？
A：根据GPS误差设置。GPS误差50米，radius设300米足够覆盖所有可能的道路。

### Q3：为什么用对数？
A：避免很多小概率相乘导致数值下溢（变成0）。对数域的加法 = 原始域的乘法。

### Q4：UBODT需要多大内存？
A：取决于路网大小和delta参数。一个中等城市（10万节点，delta=5000米）大约需要几GB内存。

### Q5：FMM和STMATCH怎么选？
A：
- FMM：批量处理大量轨迹，有足够内存
- STMATCH：实时匹配，内存受限，路网频繁变化
