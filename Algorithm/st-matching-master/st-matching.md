# ST-Matching 算法原理详解 - 通俗版

## 一、算法是什么？解决什么问题？

### 问题场景
想象一下，你有一辆车的GPS轨迹数据（一串经纬度点），但采样频率很低（比如每分钟一个点），GPS点可能偏离实际道路很远。你需要把这些稀疏的GPS点"贴"到正确的道路上，这个过程就叫"地图匹配"。

### ST-Matching 的核心思想
ST-Matching（Spatio-Temporal Matching）是一种针对**低采样率GPS轨迹**的地图匹配算法，它的核心创新是：
- **同时考虑空间和时间约束**：不仅看距离，还看时间上的合理性
- **实时计算最短路径**：使用A*算法动态计算候选点之间的路径
- **构建候选图**：将匹配问题转化为图上的最短路径问题

## 二、算法完整流程（5个步骤）

---

### 步骤1：候选点搜索 - 找GPS点可能在哪些路上

#### 1.1 为什么要找候选点？
一个GPS点可能对应多条道路（尤其在路口附近），需要找到所有可能的道路段，然后从中选出最合适的。

#### 1.2 具体怎么找？（详细步骤）

**输入**：一个GPS点（坐标：lon, lat）、网格大小（约100米）、搜索半径=35米

**第一步：确定搜索区域**
- 以GPS点为中心，画一个边长约200米的正方形（100米网格）
- 使用经纬度间隔来定义：`loninter = 0.000976`（约100米经度），`latinter = 0.0009`（约100米纬度）

**第二步：快速找出区域内的道路**
- 检查道路的起点、终点、中点是否在搜索区域内
- 使用简单的矩形范围查询

**第三步：计算每条道路的最近点**
对每个候选道路边，计算：
- GPS点到道路边的垂直距离（最短距离）
- 投影点所在的节点（matched_nd）

**第四步：筛选**
- 如果距离 <= 35米，保留这个候选点
- 否则，这条道路太远了，不要

**输出**：这个GPS点对应的候选点列表

每个候选点包含的信息：
- `edge_id`：在哪条道路上
- `matched_nd`：投影点所在的节点
- `shortest_dist`：到原始GPS点的距离（米）

**代码位置**：`STmatching_distribution_ver.py:76-86`（`get_candidates`函数）

#### 1.3 举个具体例子

```
GPS点：(116.397, 39.908)

搜索区域：
- 经度：[116.396, 116.398]
- 纬度：[39.907, 39.909]

找到的道路：
1. 道路A，距离10米，投影到节点N1
2. 道路B，距离20米，投影到节点N2
3. 道路C，距离30米，投影到节点N3
4. 道路D，距离40米，投影到节点N4  ← 超过35米，不要

候选点列表：
候选点1：道路A，距离10米，节点N1
候选点2：道路B，距离20米，节点N2
候选点3：道路C，距离30米，节点N3
```

---

### 步骤2：计算观测概率（发射概率）

#### 2.1 什么是观测概率？
观测概率 = 这个候选点真的是GPS点的可能性有多大？

#### 2.2 计算公式（高斯分布）

```
观测概率 = (1 / (√(2π) × σ)) × exp(-距离² / (2σ²))

其中 σ = 20（GPS误差标准差，单位：米）
```

**例子**：
- 候选点A：距离10米
  - 观测概率 = (1/(√(2π)×20)) × exp(-10²/800) ≈ 0.019 × 0.882 = 0.017
- 候选点B：距离35米
  - 观测概率 = (1/(√(2π)×20)) × exp(-35²/800) ≈ 0.019 × 0.193 = 0.004

**结论**：距离越近，观测概率越高（越可能是正确的）

**代码位置**：`STmatching_distribution_ver.py:88-91`（`observation_probability`函数）

---

### 步骤3：计算转移概率

这是算法的核心步骤！

#### 3.1 为什么要算转移概率？
不仅要看单个候选点是否合理，还要看"从上一个候选点到这个候选点"是否合理。

#### 3.2 具体计算步骤

**第一步：计算GPS点之间的欧氏距离**
```
欧氏距离 = 两点之间的直线距离（使用haversine公式计算球面距离）
```

**第二步：遍历所有候选点组合**
- 对时间点i的每个候选点ca
- 对时间点i+1的每个候选点cb
- 使用A*算法计算ca到cb的最短路径距离

**第三步：分情况计算最短路径**

情况1：两个候选点都是有效节点
```
最短路径距离 = A*(ca, cb) 直接计算
```

情况2：只有ca有效（cb为-1）
```
最短路径距离 = A*(ca, cb所在边的起点) + 补偿距离
```

情况3：只有cb有效（ca为-1）
```
最短路径距离 = A*(ca所在边的终点, cb) + 补偿距离
```

情况4：两个都无效
```
最短路径距离 = A*(ca边终点, cb边起点) + 两个补偿距离
```

**第四步：计算转移概率**

公式：
```
转移概率 V = 欧氏距离 d / 最短路径距离 L
```

**例子**：
```
GPS点1到GPS点2的欧氏距离 d = 200米
候选点ca到候选点cb的最短路径距离 L = 250米

转移概率 V = 200 / 250 = 0.8
```

**代码位置**：`STmatching_distribution_ver.py:94-123`（`transmission_probability`函数）

---

### 步骤4：构建候选图并找最优路径

#### 4.1 什么是候选图？
把轨迹上每个GPS点的候选点都画出来，然后按时间顺序排列，形成一个有向图。

```
时间点1的候选点：   [候选1-1] → [候选1-2] → [候选1-3]
                            ↘     ↓      ↙
时间点2的候选点：   [候选2-1] → [候选2-2] → [候选2-3]
                            ↘     ↓      ↙
时间点3的候选点：   [候选3-1] → [候选3-2] → [候选3-3]
```

#### 4.2 计算综合概率 F

综合概率 = 观测概率 × 转移概率

```
F[i][j] = N[i] × V[i][j]

其中：
- N[i] 是第i个候选点的观测概率
- V[i][j] 是从第i个候选点到第j个候选点的转移概率
```

**代码位置**：`STmatching_distribution_ver.py:126-127`（`spatial_analysis`函数）

#### 4.3 找最优路径

把问题转化为图上的最短路径问题：
- 图的边权重 = 最大综合概率 - 当前综合概率
- 使用Dijkstra算法找从起点到终点的最短路径

**代码位置**：`STmatching_distribution_ver.py:130-139`（`candidate_graph`函数）和`157-161`

---

### 步骤5：返回结果

最终输出包含：
```
{
  轨迹ID: traj_id,
  匹配边路径: [道路A, 道路B, 道路C],
  匹配节点路径: [节点N1, 节点N2, 节点N3]
}
```

**代码位置**：`STmatching_distribution_ver.py:142-168`（`trajectory_matching`函数）

## 三、核心公式（用文字描述）

### 3.1 观测概率（发射概率）
```
N = (1 / (√(2π) × σ)) × exp(-d² / (2σ²))

其中：
- d = GPS点到候选点的距离
- σ = 20米（GPS误差标准差）

含义：GPS点到候选点的距离越近，这个候选点越可能是正确的
```

### 3.2 转移概率
```
V = d / L

其中：
- d = 两个GPS点之间的欧氏距离
- L = 两个候选点之间的最短路径距离

含义：如果GPS点间直线距离和道路距离差不多，说明这条路很合理
```

### 3.3 综合概率
```
F = N × V

含义：同时考虑观测概率和转移概率的综合得分
```

```
┌─────────────────────────────────────────────────────────────┐
│                  输入：低采样率GPS轨迹                       │
│              [(116.397,39.908), (116.400,39.910), ...] │
└─────────────────────────┬───────────────────────────────────┘
                          │
                          ▼
┌─────────────────────────────────────────────────────────────┐
│  步骤1：候选点搜索（每个GPS点找候选道路）              │
│  ┌─────────────────────────────────────────────────────┐ │
│  │  1. 定义100米网格搜索区域                          │ │

│  │  3. 计算GPS点到每条边的最短距离                   │ │

└─────────────────────────┬───────────────────────────────────┘
                          │
                          ▼
┌─────────────────────────────────────────────────────────────┐
│  步骤2：计算观测概率                                   │
│  ┌─────────────────────────────────────────────────────┐ │
│  │  观测概率 = (1/(√(2π)×20)) × exp(-距离²/800)      │ │

│  └─────────────────────────────────────────────────────┘ │
│  输出：每个候选点的观测概率                           │
└─────────────────────────┬───────────────────────────────────┘
                          │
                          ▼
┌─────────────────────────────────────────────────────────────┐
│  步骤3：计算转移概率                                   │
│  ┌─────────────────────────────────────────────────────┐ │
│  │  对每对相邻时间步：                              │ │
│  │    1. 计算GPS点间的欧氏距离（haversine）         │ │
│  │    2. 遍历所有候选点组合 (ca, cb)               │ │
│  │    3. 用A*算法计算最短路径距离                   │ │
│  │    4. 转移概率 = 欧氏距离 / 最短路径距离         │ │
│  └─────────────────────────────────────────────────────┘ │
│  输出：转移概率矩阵                                   │
└─────────────────────────┬───────────────────────────────────┘
                          │
                          ▼
┌─────────────────────────────────────────────────────────────┐
│  步骤4：构建候选图并找最优路径                        │
│  ┌─────────────────────────────────────────────────────┐ │
│  │  1. 综合概率 F = 观测概率 N × 转移概率 V         │ │
│  │  2. 构建有向候选图，边权重 = max(F) - F[i][j]    │ │
│  │  3. 用Dijkstra算法找最短路径                     │ │
│  └─────────────────────────────────────────────────────┘ │
│  输出：最优候选点序列                               │
└─────────────────────────┬───────────────────────────────────┘
                          │
                          ▼
┌─────────────────────────────────────────────────────────────┐

```

## 六、与FMM算法的对比

| 特性 | ST-Matching | FMM |
|-----|------------|-----|
| **适用场景** | 低采样率轨迹（稀疏GPS点） | 高采样率轨迹（密集GPS点） |
| **最短路径计算** | 实时A*算法 | 预计算UBODT表 |
| **预处理** | 不需要 | 需要预计算UBODT |
| **查询速度** | 较慢（每次计算路径） | 极快（查表） |
| **内存占用** | 较小 | 较大（存储UBODT） |
| **核心思想** | 图最短路径问题 | 隐马尔可夫模型 + 动态规划 |
| **转移概率** | V = d/L | min(1, d/L) |
| **观测概率** | 高斯分布 | 高斯分布 |

## 七、算法参数说明

| 参数 | 默认值 | 含义 | 调整建议 |
|-----|-------|-----|---------|
| `loninter` | 0.000976 | 经度方向网格间隔（约100米） | 根据搜索范围调整 |
| `latinter` | 0.0009 | 纬度方向网格间隔（约100米） | 根据搜索范围调整 |
| `σ`（GPS误差） | 20米 | GPS误差标准差 | 根据设备精度调整 |
| `搜索半径` | 35米 | 候选点距离阈值 | GPS误差大时可增大 |

## 八、适用场景

✅ 适合：
- 低采样率GPS轨迹（如每分钟一个点）
- 实时匹配场景（无需预处理）
- 内存受限的环境
- 路网频繁变化的场景

❌ 不适合：
- 大规模轨迹数据批量处理（速度慢）
- 高采样率轨迹（效率不如FMM）
