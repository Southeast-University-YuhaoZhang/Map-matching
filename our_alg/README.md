# HMM 地图匹配算法项目

## 一、算法概述

本项目实现了一个基于 **隐马尔可夫模型（Hidden Markov Model, HMM）** 的地图匹配算法。该算法将 GPS 轨迹点匹配到道路网络上，核心思想如下：

### 算法原理

1. **观测概率**：基于 GPS 点到路段的距离，使用高斯分布计算
2. **转移概率**：基于路段之间的最短路径距离，使用指数分布计算
3. **候选点生成**：使用网格索引加速，为每个 GPS 点生成多个候选投影点
4. **Viterbi 算法**：动态规划寻找最优匹配路径

### 核心文件

- `hmm_map_matching.py`：HMM 算法核心实现
- `main.py`：主调用脚本，负责数据读取、算法调用和结果保存
- `evaluate_matching.py`：匹配结果评估脚本，支持准确率、召回率等指标计算

## 三、当前缺陷

### 路径连贯性问题

**主要问题**：绑路的路径连贯性较差，容易出现"跳边"现象。

**具体表现**：
- 匹配结果中出现横穿建筑物的路线
- 相邻 GPS 点匹配到不直接连接的路段
- 路径出现不合理的对角线跳跃

**根本原因**：
1. 边连续性约束不足，相邻匹配点可能落在不连接的路段上
2. 最短路径计算时端点判断不够精确
3. 对非直接连接的边惩罚力度不足

## 四、后续修改方向

### 优化策略

1. **增强边连续性约束**
   - 强制要求相邻匹配点所在的边必须直接连接或在合理范围内可达
   - 增加路径连续性的硬约束，而非仅通过概率惩罚

2. **改进最短路径计算**
   - 优化端点判断逻辑，更精确地确定候选点在边上的位置
   - 考虑边的实际几何形状，而非仅依赖节点连接

3. **强化速度约束**
   - 根据时间间隔和道路距离计算合理速度范围
   - 对超出合理速度范围的路径给予更强惩罚

4. **方向一致性约束**
   - 加强相邻 GPS 点之间的方向一致性检查
   - 对方向突变的路径给予惩罚

5. **后处理优化**
   - 对匹配结果进行平滑处理
   - 修复路径中的不连续点
